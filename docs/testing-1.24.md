## Follow-up upgrade checks

- On 2026-11-15 an isolated API 37.0 emulator on H: ran owner-signed 1.23 (versionCode 8), imported 420 synthetic personal and 420 synthetic family records, selected Forest after rain and saved a 10,000 BYN goal with 3,500 BYN already saved. The family report for 01-07-2026 through 30-09-2026 showed income 27,858.30 BYN, expenses 20,923.50 BYN and balance +6,934.80 BYN before update. The signed 1.24 APK (same certificate, versionCode 9) was installed with `install -r`; the profile, BYN currency, personal overall balance +3,458.40 BYN, goal and family member were visible, and the family totals matched exactly after update. Individual transaction-by-transaction comparison and biometric settings were not performed.
- On that first populated upgrade, the theme picker unexpectedly showed Night analytics after upgrade even though Forest had been selected before; the cause was not established. On 1.24, choosing Forest survived a force-stop and restart. A second clean 1.23 installation selected Forest, verified it still selected after force-stop and restart, upgraded to signed 1.24, and verified Forest was still selected. The original discrepancy did not reproduce and remains unexplained; the clean retry does not prove what happened in the first run.
- The six tests skipped solely because of special setup cover historical 1.1/1.15/1.17 upgrade paths and cross-signer migration; they were not executed in this 1.23 → 1.24 check. The app uses the same package and release signing key for this update. Cross-signer transfer is a separate restore workflow and is not evidence for a same-signer in-place upgrade.
- Follow-up on the first theme discrepancy: on a clean 1.23 installation, Forest was confirmed selected. Replaying the original rapid two-tap sequence (Back followed immediately by a tap at the former goal-screen coordinate) selected Night analytics before any update; the second tap overlapped its theme row during navigation. Night analytics then remained selected after installation of signed 1.24. This reproduces a plausible test-automation race and matches the first observation; it does not conclusively prove the exact cause in the original populated run. The independent slower Forest-selection upgrade check above still passed.
- GitHub Actions warning follow-up: the tested pinned versions run under Node.js 24 by GitHub's compatibility mode. Official `actions/upload-artifact` v6.0.0 and `ReactiveCircus/android-emulator-runner` v2.38.0 declare Node.js 24; they have not been substituted or tested in this release branch. Upgrading them is a separate CI maintenance change and would require a new GitHub run.
