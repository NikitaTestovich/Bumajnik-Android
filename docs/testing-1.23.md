# Version 1.23 verification — in progress

Version 1.23 is not released. The results below do not establish completion of release or security verification.

- On 2026-11-09, the signed 1.23 APK (SHA-256 `2b4097f5a579600c142eb0f9f8678117250b83cc001a5f37b7436f79ffaa3406`) was installed in place over 1.22 on a USB-connected test phone running Android 13. The OS accepted the update, reported versionCode 8 / versionName 1.23, and the app opened to its main navigation. The pre-update records were not independently captured for comparison, so this is not proof of complete data retention. On this phone a temporary password-protected full backup was saved and had an `FTB2` header; a wrong password was rejected and the correct password opened the restore confirmation. Restoration was cancelled without replacing the phone's data and the temporary backup file was removed. An actual restore on this phone and the GitHub download/update flow were not tested.

- On 2026-11-09, the complete `connectedDebugAndroidTest` invocation ran on a new disposable API 37.0 emulator with a device PIN: 148 cases were reported, including 133 passed, 15 assumption-based skips and zero failures; Gradle reported `BUILD SUCCESSFUL`. The skipped cases require an external fingerprint driver, process-restart orchestration or separately installed APKs and are not counted as passes. The system-PIN recovery case did run. The preceding full invocation found three failures in `BiometricSettingsRegressionTest`: the test still expected security settings directly on the More screen. After changing it to open the Security section, its three cases passed separately and in the full rerun. The previous intermittent Compose failure did not recur, but its original cause remains unknown. This run used a debug build and an emulator, not a physical device.

- JVM suite: 181 tests passed with zero errors, failures or skips after the backup cancellation fix; debug assembly also passed.
- The full Android test run was interrupted by a Compose error in AppLock. A run of the remaining classes reported 122 passed, 18 skipped and zero failures. The complete AppLockAcceptanceTest class was rerun on the Finance123 emulator with a device PIN: all 6 tests passed, with no skips or failures. The initial failure did not recur; its cause has not been established. These results are not a completed clean full Android run.
- Gradle debug and AndroidTest builds and `compileReleaseKotlin` succeeded. A locally signed 1.23 APK (versionCode 8) was verified to use the 1.22 release certificate. On the disposable FinanceUpgrade emulator, a signed 1.22 install with one synthetic 123.45 USD income was upgraded in place to signed 1.23; the income, displayed balance, profile name and USD currency remained. Other data types and settings were not covered by this upgrade check.
- A real XLSX exported from signed 1.23 on FinanceUpgrade opened with openpyxl 3.1.5: the synthetic owner and income 123.45 were retained, text fields were strings and income was numeric. On 2026-11-09 LibreOffice 26.8.2.2 processed and saved a copy of that export in headless Calc; the owner, income and currency were retained. A separate synthetic workbook produced by the compiled app spreadsheet codec was also round-tripped through LibreOffice: five comments including `=1+1`, `+1+1`, `-1+1` and `@SUM(1;2)` remained text, normal expense amounts remained numeric, a large amount remained exact text, and the result had no formula cells. The signed app export itself contained one ordinary income and did not contain formula-like input. A PDF exported through LibreOffice showed that default column widths clip the displayed record ID; the full value remains in the spreadsheet. The graphical Calc UI and Microsoft Excel were not tested.
- A password-protected FTB2 backup made on FinanceUpgrade was transferred to a separate FinanceBackup emulator running signed 1.23. A wrong password allowed a retry; the correct password restored the synthetic profile, USD currency, income and balance. This cross-device case did not include family data, settings or biometric protection. During this test cancelling the password after selecting a destination created an empty file. The later fix requests the password first: four targeted UI tests passed on FinanceBackup, including cancellation before picker (observed failing before the fix), cancellation of picker, creation and restoration. The release APK used for the cross-device test predates this fix and must be rebuilt and signed again. If Android kills the process while the picker is open, a selected file may still be left empty; the password is deliberately not persisted.
- A separate FinanceExtended emulator was upgraded from signed 1.22 to signed 1.23 after importing 420 synthetic family records and setting a goal and theme. Family aggregate totals, the 10,000 / 3,500 goal and Electric graphite theme remained visible after upgrade. Individual family rows and all other settings were not checked.
- After the cancellation fix, a newly signed 1.23 APK (SHA-256 `2b4097f5a579600c142eb0f9f8678117250b83cc001a5f37b7436f79ffaa3406`, versionCode 8, same signing certificate) was installed over the preceding 1.23 on FinanceExtended. The family totals and goal remained visible. Cancelling the password dialog left the Downloads listing unchanged. An encrypted backup was transferred to FinanceBackup running the same signed APK; its preview showed 420 family records, and after restoration the profile, family aggregate totals, 10,000 / 3,500 goal and Electric graphite theme were visible. This case contained no personal operations; individual family rows were not compared. Separately, on clean FinanceFinal, signed 1.22 was upgraded directly to this exact APK: one synthetic income of 123.45 USD and the displayed balance remained.
- The owner selected CSV size limits and splitting oversized data into smaller exports. CSV currently enforces a 10 MiB input/output limit, up to 100,000 records and 65,536 characters per field. This records the chosen approach, not completion of every large-file or split-workflow test.

Before release, assess the earlier intermittent Compose failure; verify skipped cases where applicable, broader upgrade data retention, backup recovery with family data and settings, XLSX in Microsoft Excel, and the remaining checks in the 1.23 plan. The physical-device check is limited to the scenarios described above.
