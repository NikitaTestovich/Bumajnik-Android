# Version 1.20 testing — work in progress

## Status

Not ready for public release: the GitHub update flow and migration on the intended physical phone remain unverified. Emulator migration, backup, screenshots and signing have been exercised as described below; no existing personal installation was modified.

- A separate empty public repository was created for releases; the checker and approved asset URL were switched together. A regression test first failed on the new location, then passed after the change. The full JVM suite passed 158 tests, and the debug app and Android test APK assembled. Real GitHub release download and a newer-version installation have not yet been tested.
- `:app:assembleDebug :app:testDebugUnitTest :app:connectedDebugAndroidTest`: successful on the disposable API 37 emulator. JVM: 155 tests, zero failures. Android: 128 cases, zero failures, including 19 assumption-based skips; skipped cases are not counted as passes.
- A subsequent full JVM run after adding offline-download and redirect-loop checks passed 157 tests with zero failures. Both new checks verify that the temporary download is removed on failure.
- Review found that full-backup validation rejected some UUID representations accepted by existing CSV imports. A regression test reproduced the failure; validation now preserves the exact identifiers. After the fix, all 158 JVM tests and both focused in-memory Android database capture/restore tests passed. The debug bridge archive was rebuilt and verified. The owner rebuilt the release with the same certificate, and the revised APK was installed over the previous 1.20 release on the test phone with the fictional personal balance retained. This does not test a higher-version update or GitHub download.
- Staged signing migration and fingerprint scenarios were exercised separately as documented below. Destructive instrumented fixtures now check both emulator properties before touching data and are not intended for a personal phone.
- The requested root `AppAndroidBudjets.zip` now contains the 1.20 debug APK (versionCode 5); its extracted SHA-256 matches the built APK. It is a test/bridge build signed with the existing debug certificate, not the production release. The previous archive was retained locally in the ignored `.superpowers` directory.
- The owner built a release APK using the owner-managed keystore. Android build tools verified its signature, package `com.personalfinance.tracker`, versionName 1.20 and versionCode 5. Its signer differs from the previous debug signer. A release-key migration on a physical device and the GitHub update flow have not yet been verified.
- The owner-signed APK was installed on the disposable API 37 emulator and Android reported `MainActivity` resumed. The package manager recorded this as a fresh install. This smoke check does not verify a release-to-release update or data migration.
- On the disposable emulator, an existing synthetic full-backup file from the old-signature bridge test was selected through Android's document picker and restored into the actual owner-signed 1.20 release APK. This verifies a representative personal-data transition to the actual release signer; it does not prove recovery of a particular user's files or interruption safety.

Transferred that synthetic file to the separately installed owner-signed release on the emulator and restored it via the system picker: 2 added, 0 duplicates. ## Required before release

- Execute Android UI and E2E tests on disposable data, including search, scrolling, category drilldown, four themes, both languages, large text and intermittent chart visibility.
- Extend real-picker CSV coverage across providers and verify the complete cross-signature migration using user-operated files and disposable installations.
- Test full backup export, corruption rejection, replacement confirmation, database rollback, preference restoration and lock re-enrollment on disposable installations. Database and preference writes use distinct stores and are not one atomic operation; simulate failures and interruption.
- Verify full-data migration from the actual 1.17 signing certificate to the intended production release certificate. The existing 1.17 CSV backup does not include family data and settings. A matching-signature bridge build and a securely stored full backup are required before replacing a real installation; the staged emulator test above used a disposable second key.
- Exercise GitHub check, redirects, offline/rate-limit errors, checksum/signature mismatch, Android install confirmation, and retained data using a non-production release and matching signing keys.
- Review changed code and security, update both user guides and specifications, then build and verify release artifacts. Do not publish keys, real backups or APKs in Git.
