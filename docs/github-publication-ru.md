# Публикация Finance Tracker и обновления через GitHub

## Как устроен доступ

Для публикации создан отдельный публичный `NikitaTestovich/Bumajnik-Android`; приложение проверяет его раздел Releases без токена. Не переносите в публичный репозиторий старые ветки или pull request из приватной истории: используйте только подготовленную очищенную копию.

Если сделать репозиторий публичным, любой сможет просматривать его содержимое и историю, скачивать опубликованные релизы и создавать свои копии (fork). Прямой доступ к изменениям исходного репозитория автоматически другим пользователям не выдаётся: они могут предложить изменения, а владелец решает, принимать ли их. Не приглашайте других людей в Collaborators, если они не должны иметь доступ на запись. Регулярно проверяйте разрешения GitHub Apps и других интеграций.

Бесплатное скачивание APK не требует включать оплату или спонсорство. Публичность репозитория сама по себе не определяет все разрешения на использование исходного кода; вопрос лицензии владелец может решить отдельно.

## Прежде чем менять приватность

1. Проверьте не только текущие файлы, но и историю коммитов, изображения, вложения, имена и адреса авторов. В истории обнаружены адреса, не являющиеся GitHub noreply, включая адрес домена Gmail. При открытии они могут стать публичными. Если адрес нужно скрыть, отдельно спланируйте очистку истории до публикации и согласуйте последствия для существующих клонов.
2. Не добавляйте в Git файл релизного ключа, пароли, реальные CSV/резервные копии или локальные настройки SDK. Храните резервные копии ключа и пароля отдельно и безопасно.
3. Проверьте пользовательский путь переноса данных со старой тестовой подписи. На эмуляторе проверен перенос вымышленных личных данных; это не подтверждает восстановление конкретной личной копии. До проверки не удаляйте установленное приложение.
4. Подтвердите выпуск только после итоговых тестов и проверки работы обновления из GitHub.

Открывать исходный приватный репозиторий не требуется: приложение настроено на отдельный публичный репозиторий.

## Подготовка изменений через GitHub Desktop

Очищенная версия 1.20 подготовлена в локальной копии `H:\AI\AppAndroidBudjets\.worktrees\version-1.20-public-clean`, ветка `feature/version-1.20`. Её Git-история не содержит обнаруженный адрес Gmail; не подключайте для публикации старую рабочую копию. Перед отправкой проверьте, что `origin` указывает на `https://github.com/NikitaTestovich/Bumajnik-Android.git`, а в список изменений не попали ключи, реальные выгрузки и локальные настройки. Через **File → Add local repository** откройте очищенную копию в GitHub Desktop. Порядок отправки новой пустой репе: сначала опубликуйте очищенную ветку `main`, затем `feature/version-1.20`, после чего создайте pull request в `main` и проверьте изменения.

## Выпуск и обновления

После принятия изменений создайте на GitHub релиз с номером версии и описанием изменений. Добавьте проверенный релизный APK с именем `finance-tracker-vc5.apk` для версии 1.20 с `versionCode` 5. Следующим версиям требуется возрастающий `versionCode` и соответствующее имя файла. Проверяйте, что опубликованный файл подписан тем же сохранённым релизным ключом, а метаданные GitHub предоставляют SHA-256 digest. Текущий код приложения ищет последний опубликованный стабильный релиз; черновик и предварительный выпуск этому условию не соответствуют.

Сначала нужно отдельно проверить получение релиза, загрузку файла, проверку подписи и подтверждение установки Android. Обновление поверх существующей релизной установки требует совпадающих package ID и подписи и более высокого `versionCode`; Android может запросить подтверждение установки. Старый APK с другой подписью требует переноса данных.
