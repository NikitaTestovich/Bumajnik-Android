# Optional app protection — version 1.15

Protection is disabled until the user enables it in Profile. A device screen lock must already be configured. The user sets and confirms a masked application code of 4–10 characters; enrolled device biometrics may be enabled as an alternative unlock method.

The app requires authentication on a fresh launch, after at least 30 seconds outside the app, and when the phone locks. With biometric unlock enabled and available, a new locked session opens Android's biometric prompt automatically and hides the app-code field until biometric authentication fails, is canceled, or becomes unavailable. Then the code screen appears; the user can explicitly retry biometrics when available. An old prompt response cannot unlock a later session. A brief visit to the Android file picker does not require another unlock. Locked users cannot access financial screens or bypass the gate with Back. When protection is active, app content is hidden from screenshots and recent-app previews.

Five incorrect code attempts cause a 30-second pause. Restarting the app or changing the wall clock does not clear it. A reboot during a pending pause may start a fresh 30-second pause. Changing or disabling protection requires the current code. If the code is forgotten, successful confirmation of the phone's system PIN, password, or pattern disables the forgotten app protection while preserving financial records; cancellation changes nothing.

The code is never stored in plaintext. A salted, slow verifier is held in app-private storage protected with Android Keystore. Biometric matching takes place in Android's system prompt. Neither the code verifier nor protection preferences are included in CSV exports. This feature is an application access lock; it does not encrypt exported CSV files or the finance database.

Automated coverage includes code rules, retry policy, lock lifecycle, settings changes, cancellation, blocked navigation, emulator system-PIN recovery and actual Android biometric prompts on an enrolled emulator. The connected physical phone displayed the automatic prompt after the user enabled biometrics; a successful physical match and failure/recovery matrix have not been independently confirmed.
