# Version 1.17 — themes and savings goal

Status: implemented; release verification is recorded in [testing-1.17](../testing-1.17.md). Whole-branch review findings were addressed in commit 442e070 and passed scoped independent re-review; the later Home/export changes in f25fa42 passed independent specification and quality review. Visual references: locally retained design sets 1–9 and `.superpowers/designs/goal-progress-117-refined.html` (A2). These prototypes are ignored local references, not release assets.

## Intent and alternatives

Offer a choice of four distinct designs throughout the Android app and give savings progress more presence. The user chose designs 2, 6, 8 and 9, with 2 as the default. For goal progress the user selected A2, a wide segmented bar. Alternatives considered were A1, a continuous bar, and the earlier ring and milestone-list concepts.

## Themes

- Profile has a «Темы» / «Themes» section with clear previews, names, the current selection and accessible selection controls. Changing a theme applies immediately and persists across app restarts and updates.
- Available themes: 2 «Финансовый журнал» / Financial journal; 6 «Электрический графит» / Electric graphite; 8 «Цветная мозаика» / Color mosaic; 9 «Ночная аналитика» / Night analytics. Match the selected prototype's layout and visual character across the app, adapting each screen while preserving its existing capabilities. Themes 6 and 9 are dark; 2 and 8 are light.
- Reference characteristics: 2 uses warm light #F5F3EE, slate #445C77 and ochre #946536, compact rows and a strict grid; 6 uses graphite #181818, blue #9AAEFF and mint #A7EFB5, with modular cards; 8 uses lilac #F2EDFF, violet #6744CB, pale lemon #EADF7E and blue #C8E8F5, with a mosaic of differently sized cards; 9 uses graphite #181818, turquoise #68DCCD and orange #FFC078, with horizontal breakdown bars. These values express visual direction; adjust foreground colours as needed for contrast.
- All screens and states follow the selected design, including onboarding, lock, navigation, entry forms, profile, family, reports, goal, dialogs, charts, empty and error states. Keep text legible, provide accessible contrast and touch targets, and do not rely on colour alone for meaning. Preserve existing green positive / red negative semantics and signs, with suitable contrast in every theme. Retain Russian and English.
- Expense breakdown and reports retain readable amounts, category labels and percentages. Theme 9 may use the horizontal bars shown in its reference while retaining all data and selection accessibility. Other themes retain the approved ring where applicable.
- Define stable internal theme IDs and a central registry of available themes. New themes can be added and existing ones removed without resetting unrelated data; an absent, invalid or retired stored ID falls back to the registry's available default, initially theme 2. If theme 2 is removed in a future release, that release must appoint another available default. New and existing 1.15 installations without a theme setting use theme 2. Theme selection is a local appearance preference; it does not alter currency, records, CSV or backups.
- Consolidate fixed palette usage into theme-aware tokens. Do not assume changing only the Material colour scheme is sufficient: current UI also accesses FinancePalette directly. Apply the same theme to the lock screen and normal navigation.

## Savings goal: option A2

- On the goal screen, replace the thin indicator with a prominent wide bar of four equal segments, labelled 0%, 25%, 50%, 75%, 100%. Fill each segment according to actual savings, including partial fill in the current segment. Show progress as a percentage, saved amount, goal amount, remaining amount, and the amount required to reach the next milestone. The compact goal block on Home retains its compact footprint and follows the active theme; the full segmented display is on the goal screen.
- Completion at or above the goal shows a full bar and a clear completed state; remaining and next-milestone amounts are not negative. Display actual saved amount even if it exceeds the goal. When no goal exists show the existing entry guidance. The user can continue editing the target and saved amount.
- When the goal uses the current currency, show its factual progress even if exchange rates required for a forecast are missing; request those rates for the forecast. After changing the main currency, the app automatically converts and saves the target and saved amount when all required rates match the forecast period and new currency. Missing rates are requested; the original goal remains until they are supplied. If conversion cannot be calculated (for example, no completed forecast period exists or the converted amount is invalid), re-enter both amounts in the new currency and save the goal. Do not display invented dates, prior increases or percentage changes: existing stored data contains no historical goal snapshots. Forecast uses the existing completed-month calculation and existing no-data/no-positive-surplus states. Display a duration only when the current forecast provides one.
- Adapt bar and milestones to each theme; support large text, narrow screens, Russian and English, and screen readers. Text labels explain progress and next milestone without requiring colour perception.

## Operations, icon picker and biometric upgrade feedback

- Operations remembers the user's last selected Income or Expenses tab across navigation and process restart. After adding or editing an income or expense, returning to Operations selects the corresponding tab. Preserve selection when abandoning a form without saving. The two tab targets fill the available width equally and remain accessible in both languages and at large text sizes.
- The category icon picker offers a user-controlled switch between labelled and unlabelled icons; default to the existing labelled presentation. Preserve the selected icon and offer an accessible description even when labels are visually hidden. Remember the display preference without changing existing category data or icon identities. Explain neutral icon association through selection; do not imply an icon restricts category use.
- Investigate the user's report that biometrics required reconfiguration after upgrading on a personal phone. Reproduce or establish concrete causes where possible, fix confirmed causes without weakening protection or losing records, and transparently report any remaining uncertainty. An in-place upgrade from 1.15 with app protection and biometric preference enabled must preserve both preferences and existing data; temporary sensor unavailability must not silently erase the user's enabled preference. Test enabled and disabled biometrics, temporary unavailability and recovery, and real upgrade on disposable emulator where feasible.

## Builder choices

Implement with the existing Kotlin, Compose and local storage stack. Choose precise layouts, theme token structure and motion appropriate to each design. Calculate milestones using integer minor units and round a fractional threshold up to the next minor unit. Show percentage rounded down to at most one decimal place, so rounding cannot imply an unreached milestone; calculate fill and remaining amounts without overflow. Confirm user-facing states remain coherent for all themes.

## Version 1.17 Home and export update

Monthly expenses is visible for new installations, missing preference entries and Restore defaults. Users can hide it; saved visibility (including previously hidden expenses) and order are retained. Reports always export the current eight-column CSV including income comments; the version 1.1 checkbox is removed. Version 1.1 cannot read these exports. Seven-column import remains supported. A pending export retains its chosen period through recreation and writes current format.
