# Создание ключа подписи релиза

Ключ нужен для подписи будущих APK и возможности устанавливать обновления поверх той же релизной версии. Выполните эти шаги самостоятельно: пароль и файл ключа не нужно отправлять в чат, добавлять в Git или публиковать.

1. Откройте PowerShell на компьютере.
2. Создайте папку вне репозитория:

   ```powershell
   New-Item -ItemType Directory -Path 'H:\AndroidKeys' -Force
   ```

3. Запустите создание ключа. Команда использует `keytool` из установленной Android Studio и задаёт обезличенное имя сертификата:

   ```powershell
   & 'H:\Android studio\jbr\bin\keytool.exe' -genkeypair -keystore 'H:\AndroidKeys\FinanceTracker-release.jks' -storetype PKCS12 -alias finance-tracker -keyalg RSA -keysize 3072 -validity 10000 -dname 'CN=Finance Tracker, O=Personal, C=BY'
   ```

4. Дважды введите придуманный пароль хранилища, когда программа попросит. Ввод может не отображаться на экране — это нормально. Сохраните пароль в менеджере паролей; при утере ключа или пароля будущие обновления с этой подписью могут стать невозможны.
5. Убедитесь, что файл `H:\AndroidKeys\FinanceTracker-release.jks` создан. Сделайте защищённую резервную копию ключа отдельно от компьютера и сохраните пароль отдельно от файла.

Не удаляйте установленное приложение. Новый релизный ключ отличается от тестовой подписи установленной версии: перед заменой потребуется полная резервная копия и проверенный перенос. Сначала сообщите только, что ключ создан; сам файл и пароль передавать не нужно. Публиковать APK пока не требуется.

## Локальная сборка с ключом

После создания ключа можно выполнить в PowerShell из рабочей копии проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build-release-local.ps1
```

Скрипт попросит пароль в окне PowerShell и подпишет APK. Пароль не появится при вводе; он передаётся только дочерним процессам проверки и сборки и не сохраняется в файлы проекта. Результат находится в `android\app\build\outputs\apk\release\app-release.apk`. Не публикуйте его до проверки сертификата, восстановления данных и обновления через GitHub.
